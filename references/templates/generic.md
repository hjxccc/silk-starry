# 模板：通用项目 CLAUDE.md 骨架

> 用于探测不出明确技术栈、或想要最小起点时。填完务必做减法（逐条过准入门槛）。
> 占位符 `<...>` 替换，删掉用不上的整段。目标 ≤200 行，理想 ≤60。

```markdown
# CLAUDE.md

## 项目概述
<一两句话：项目是什么 + 核心技术栈>

## 构建与运行
- 安装依赖：<cmd>
- 启动开发：<cmd>
- 运行测试：<cmd>
- 提交前必跑：<lint + test 组合>   # 官方明确推荐写的内容

## 代码偏好（仅列与默认/主流不同的）
- <例：日志用 X 不用 Y，因为…>

## 踩坑（不写就会中招的非显而易见行为）   # 对标 Anthropic claude-code-action 的 "Things That Will Bite You"
- <例：search_code 只是 RAG 辅助，定位优先 glob → grep → read>
- <例：改了命令入口要同步 Main + Parser + 测试 + 文档>

## 禁区
- 不要 <危险操作>（原因：…）
- 不要改 <自动生成/已发布 的文件>

## 工作方式
- 影响 >3 个文件先列计划再动手。
- 不确定就停下来问，别静默假设。
```

填写提示：
- "项目概述"一句话即可，别写架构罗列（Claude 读代码就知道）。
- "代码偏好"只写**与默认不同**的；和主流一致的别写。
- "禁区"是性价比最高的部分——把你踩过的坑写成"不要做 X"。
