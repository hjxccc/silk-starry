# 第三层文档同步：代码改了，docs/README 跟着别烂（顺带能力）

> **定位（以 CLAUDE.md 为主）**：silk 的主体始终是 **CLAUDE.md / 记忆契约**（给 AI 看的）。这一层是**顺带的"过期提示"**——
> 当某次改动同时波及 `docs/`、`README`、`runbook` 时，silk **把它指出来**，**不接管人类文档的写作、不替你重写 docs**。
> 守 silk 一贯红线：**只检测 + 给建议 + 给 diff 等你确认**。
> 触发：会话/任务收尾、"整理一下文档"、"这次改动文档要不要跟着改"、改了路由/环境变量/数据表/技术栈之后。

## 一、三层知识，受众不同、不许重复
一个项目的知识分三层，受众和位置都不同，更新方式也不同：

| 层 | 给谁看 | 放什么 | 不同步的后果 |
|---|---|---|---|
| **Auto Memory** | 未来的自己（跨会话） | 项目事实、偏好、外部指针 | 下次会话丢历史上下文 |
| **CLAUDE.md / AGENTS.md** | 同一个 AI 的后续会话 | 规则、结构、红线、环境变量 | AI 在同项目里重复犯错 |
| **`docs/` + `README`** | 外部的人 / 下游系统 / 别的 agent | 接入指南、架构说明、运维手册、交接 | 外人/下游接不进来、跑不起来 |

**不许跨层重复**：CLAUDE.md 写"新增了 5 个路由"（提醒自己的规则）；`docs/integration-guide.md` 写"下游怎么消费这 5 个路由"（教别人）——作用不同，都要写，但**不互相抄正文**。silk 的核心始终在前两层；第三层只在"它确实因这次改动过期了"时才顺带提示。

## 二、变更影响矩阵（改了 X → 哪几层会过期）
收尾/审查时不要只看"对话里改了啥"，要查这些改动**波及哪些文档层**：

| 这次改动 | 可能过期、需提示同步的地方 |
|---|---|
| 新增 API 路由 | CLAUDE.md 路由清单 + `docs/integration-guide` + 架构图 Routes |
| 新增环境变量 | CLAUDE.md env 表 + `runbook` + 下游 integration-guide |
| 新增数据库表 | CLAUDE.md + 架构 Data Model |
| 换技术栈/依赖（如 SQLite→PostgreSQL） | CLAUDE.md + README + runbook + 所有提到旧栈的 docs |
| **跨项目改动**（改了 A，B 依赖 A 的 SDK/API/env） | **A 和 B 两边的文档都要对齐** |

**跨项目检查（必问一句）**：这次对话是不是跨项目的？若改了项目 A 而项目 B 通过 SDK/API/环境变量依赖它，**B 的文档也得同步**——对每个受影响项目都跑一遍"枚举 + 读"，别假设改完 A 就够了。

## 三、机械式枚举（先列清单，再判断——防漏）
判断前先无遗漏地列出，给每个文件标 `已看 / 需改 / 无需改`：
1. 跑 `python scripts/scan.py <项目根>`：CLAUDE.md / AGENTS.md 清单。
2. 补第三层：`docs/*.md`（含"根本没有 docs/"这个事实）、散落各处的 `.md`、`README*`、`CHANGELOG`、`runbook`。
3. 通读本轮对话，对照变更矩阵标记每个文件。
> 漏文件是这类任务最主要的失败模式——宁可多列，别静默跳过那个"偏偏漏了的关键文档"。

## 四、减优于加（同 `writing-rules.md`「越短越灵」一脉相承）
- **先减后加**：先删不该存在的（已完成的计划、被推翻的决策、过期条目、一次性事后复盘），再补这次缺口。
- **删除优于保留 · 合并优于追加 · 精确优于冗长**：改已有条目而非追加重复；一条记忆 = 一个事实。
- **净增红线**：一次同步让 CLAUDE.md **净增 >30 行**就要警惕——多半把"叙事历史"写进去了；规则只有"下个 AI 不看就会写错"才留，其余移到 docs 或删。
- **指针不重复**：一个事实在"深潜文档"引用表里出现一次即可，别在叙事里再说一遍。
- 软上限：CLAUDE.md ≤200 行（理想 ≤60，见 `writing-rules §2` 的 IFScale 实证）；单条记忆 ~100 行；单个 `docs/*.md` 别无限膨胀。

## 五、改动顺序 + 结构化变更摘要（收尾必出）
**改的顺序**：外部 docs（影响面最大）→ CLAUDE.md / AGENTS.md → 记忆。每一步都走 silk 红线：**给 diff、等确认、最小改动**。

收尾给用户一份摘要（只列变了的，不列没动的）：
```
## 同步完成
### 记忆变更
- 更新：xxx（原因）
- 删除：xxx（原因）
### 文档变更
- <project>/CLAUDE.md — xxx
- <project>/docs/integration-guide.md — xxx
### 未处理（需你定夺）
- xxx（为什么没动：如两条记忆矛盾、拿不准受众）
```

## 六、🔴 守住 silk 的边界
- silk **不自动改 docs/README**——检测出"该同步哪些"后，给清单 + diff，**等你确认**再改。
- 第三层同步同样过敏感信息扫描（别把密钥写进 README/runbook）。
- 绝对时间：docs 里的"昨天/最近"同样要转绝对日期（与 `memory_doctor` 的相对日期检测同理）。
- 拿不准受众/有矛盾 → 进"未处理"让用户定，别硬改。
- **主次分明**：第三层是顺带提示，**不喧宾夺主**；silk 的价值锚点永远是"把给 AI 的 CLAUDE.md/记忆契约写好、保持精简、不过期"。
